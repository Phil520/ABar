# ABar v2.0.0

macOS 菜单栏上的上证指数看板。菜单栏只放一行数字，不写「上证指数」四个字。

![菜单栏效果](docs/images/menubar.png)

```
37230.31        ← 3723 点 + 0.31%，绿色表示下跌
```

点位取整数，涨跌幅取绝对值两位小数，直接相连。没有逗号、百分号、正负号，方向只靠颜色。
等宽数字，数字跳动时宽度不抖。左键点开详情，右键出菜单。

## 颜色

| 方向 | 浅色菜单栏 | 深色菜单栏 |
| --- | --- | --- |
| 涨 | #D61719 | #FF5C57 |
| 跌 | #00783D | #33D16B |
| 平 | 系统默认前景色 | 同左 |

断线两次以上：保留最后一次的值，整体转灰。

## 数据

腾讯行情为主（`qt.gtimg.cn`），新浪为备（`hq.sinajs.cn`），任一可用即显示。

刷新频率按北京时间算（不跟随系统时区）：交易中 10 秒，其余 60 秒；
还没拿到过数据时 5 秒重试，避免对着占位符干等一分钟。

## 什么时候运行、什么时候关闭

只有**交易日 08:00–16:00** 才在菜单栏露面。其余时间一律关闭：

| 时段 | 状态 |
| --- | --- |
| 交易日 08:00–16:00 | 运行：菜单栏显示、按节奏刷新 |
| 交易日 16:00–次日 08:00 | 关闭：菜单栏项隐藏、不联网、不刷新 |
| 周末 | 关闭 |
| 法定节假日（休市） | 关闭 |

关闭时不是把进程杀掉，而是把它藏起来：菜单栏上没有痕迹、不发网络请求、只剩一个
每 5 分钟醒一次的心跳，到 08:00 准点自己回来。这么做是因为 `launchctl` 在这台机器上
装不进去（一直返回 `Input/output error`），真退进程就没人能在早上把它叫起来。

休市日按上交所 2026 年安排内置：元旦 1/1–1/2，春节 2/16–2/20、2/23，清明 4/6，
劳动节 5/1、5/4、5/5，端午 6/19，中秋 9/25，国庆 10/1、10/2、10/5–10/7
（周末本来休市，不重复列）。来源是上证公告〔2025〕45 号。

每年 12 月交易委会发下一年的安排，届时补表即可——不改代码也行，往
`~/Library/Application Support/IndexBar/holidays.txt` 里按 `YYYY-MM-DD` 一行一个写，
优先级高于内置表。

核对当前判定：

```bash
./output/指数条.app/Contents/MacOS/IndexBar --session-check
```

它会把「现在该不该运行」和一组典型时刻（开盘前、开盘、午休、收盘前、收盘、夜里、
周六、周日、国庆、春节、节后首日）的判定一次打出来，不建界面、不常驻。

右键菜单里有「现在收起到下次开盘」，可以手动提前关。

## 构建与启动

```bash
bash build.sh                # 编译 + 上屏自检
SKIP_TESTS=1 bash build.sh   # 只编译
open "output/指数条.app"
```

## 上屏自检

```bash
swiftc -O -framework Cocoa -o /tmp/menubarcheck tools/menubarcheck.swift && /tmp/menubarcheck
```

判据是「控制中心菜单栏层里到底有没有这块窗口」，不是「进程有没有起来」。
进程在跑、标题也设上了、窗口却被推到屏幕外——这台机器上真实发生过，所以只能这么查。

## 踩过的坑

**菜单栏状态项不显示，八成是被菜单栏管理工具挤出了屏幕。**

这台机器装了 `Hidden Bar`，它会在菜单栏插一根 **宽 5016 像素** 的占位条
（窗口名 `hiddenbar_separate`），把「隐藏区」的项整体推到屏幕左边缘之外。
新装的状态项默认就落在那一片，表现就是进程在跑、菜单栏上什么都没有。

查法：看窗口服务器里状态项窗口的 x 坐标。

```
x= -3952.0  w=81.0    Item-0
x= -3871.0  w=5016.0  hiddenbar_separate   ← Hidden Bar 的占位条
```

修法是让状态项的位置值**小于折叠箭头的值**（值越小越靠右）：

```bash
defaults write com.bean.indexbar.menubar "NSStatusItem Preferred Position IndexBarItem" -int 150
```

实测：295 是 Hidden Bar 的折叠箭头，327 是它的占位条，大于 295 的值都会被挤到屏幕外；
150 落在 x=1170，正常可见。

**怎么判断到底上屏没有**：看状态项窗口的高度。33 才是被控制中心托管的真窗口；
22 是进程自己的占位窗口，等于没上屏。日志里的自检行直接写这个：

```
12:06:56 [V2] 自检 窗口高33 已上屏
```

另外三条同源经验：

- 首屏文字不要用「—」这种窄字。系统会先按 32pt 的默认宽度定好槽位，之后读数变宽，
  槽位不重新让位，右边就被切出屏幕。首屏用等宽占位串。
- 菜单栏文字配色必须是**普通静态色**。`NSColor(name:dynamicProvider:)` 那种带闭包的动态色
  过不了进程边界，深浅色适配改成渲染时按按钮 `effectiveAppearance` 现算。
- 关闭显示用 `statusItem.isVisible = false`，**不要用 `removeStatusItem` 反复销毁重建**。
  反复拆建会让控制中心把这一份 bundle id 的状态记成坏的，之后同一个 id 再也托管不上——
  今天就是这么把 `com.bean.indexbar.app` 跑坏的，只能换 id。

## 目录

```

src/Info.plist            App 配置

tools/menubarcheck.swift  上屏自检：查窗口服务器里到底有没有这块窗口
tools/com.bean.indexbar.autostart.plist  登录自启模板（含每天 08:00 定时）
docs/开发笔记.md           排查记录，菜单栏踩坑都在这
legacy/v1/                早期多文件实现，已停用，只作对照
output/指数条.app          产物（不进版本库）
```

App 的显示名是「指数条」，仓库名是 ABar。

## 环境要求

macOS 13 以上，装了 Xcode 命令行工具（`swiftc` 可用）。不需要 Xcode 工程，`build.sh` 直接调 `swiftc`。

## 已知限制

- 只在 macOS 26 上实测过
- 行情来自公开接口，腾讯和新浪任一不可用就靠另一个；两个都挂时显示最后一次的值并转灰
- 休市表目前只有 2026 年，跨年要补
